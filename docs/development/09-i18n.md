# 9. Languages (i18n)

## Languages

| Code                   | State                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------ |
| `en`                   | Source of truth. Every key lives here first                                                            |
| `hi`                   | **Required**: must have exactly the same keys as `en`. First draft, needs a native review              |
| `ta`, `zh`, `ko`, `ja` | Optional first-draft overlays. Keys must exist in `en`; a missing key falls back to English at runtime |

The app uses `i18next` + `react-i18next` (`i18n/index.ts`, `lng: 'en'`, `fallbackLng: 'en'`). Each language's label is always in its own script so people can find it
whatever language is on. The language is saved under `svaraa.language` and restored at start (`features/settings/language.ts`).

## Rules

- No hard-coded text anywhere in `app/`, `features/` or `ui/`: use `const { t } = useTranslation()` and `t('namespace.key')`.
- Components take **already translated** strings (`<Button label={t('...')} />`).
- Keys are nested by area (`auth.welcome.terms`, `errors.invalid_otp`, `apps.name.news`, `wearer.consent`). Add yours under your feature's namespace.
- Placeholders must match across languages (`{{name}}`); `i18n:check` compares them.
- Every API error code needs `errors.<code>` (see [Backend integration](05-backend-integration.md)).
- Use "caregiver" and "household" in English text; the Hindi wording must express the same.
- Hindi addresses both genders in some lines (B1 uses "पहनूँगा/पहनूँगी"). Check wording with a native speaker.

## Check

`npm run i18n:check` (`scripts/i18n-check.ts`) fails when:

1. `en` and `hi` differ in keys, a value is empty, or placeholders differ;
2. a `t('key')` call uses a key missing from `en.json`;
3. a screen or component has hard-coded JSX text or a `label` / `title` / `placeholder` string prop.

CI and `npm run check` run it.

## Fonts and scripts

`ui/fonts.ts` loads Newsreader and Inter for Latin text and Noto Sans for Devanagari, Tamil, Japanese, Korean and Simplified Chinese.
`<Text>` picks the face from the active language, and `scriptLineFactor()` raises line height for scripts that need it. Always render text through `<Text>`.
Check Hindi for clipped text in buttons and cards (longer than English), at display size 3.

## Add a language

1. Create `i18n/<code>.json` (copy `en.json`; translate what you have, delete what you do not: it falls back to English).
2. In `i18n/index.ts` add the import, the `resources` entry, the `Language` type, `LANGUAGES` and `LANGUAGE_NATIVE_LABEL`.
3. In `scripts/i18n-check.ts` add the code to `PARTIAL` (or to `FULL` for full parity).
4. Add a font for its script in `ui/fonts.ts` if the existing ones do not cover it.
5. Check it appears in the language picker (`ui/LanguageSwitch.tsx` and the Profile language setting; confirm whether they read `LANGUAGES`).
6. `npm run check`, then look at long screens in the new language.

## Server-side languages

The wearer's spoken languages are free-text names on the server; the app maps common names to codes (`features/wearer/languages.ts`). News has its own
languages (`en`, `hi`). Voice recognition on the server is Hindi only for now. These are separate from the UI language.
